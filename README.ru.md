# zcode-discord-rpc

[English](README.md)

**Discord Rich Presence для [ZCode](https://z.ai).** Показывает в твоём Discord-профиле текущий проект и чем прямо сейчас занят агент:

```
Играет в ZCode
Working on my-project        ← имя воркспейса
Running a shell command      ← живая активность агента
44:12 elapsed                ← таймер сессии
```

Отображаемые состояния: «думает» (с опциональным превью промпта), запускает инструменты (Bash, Edit, Read, Grep, Agent, …), ждёт разрешение, чинит ошибку инструмента, ожидает ввода между сообщениями.

## Как устроено

```
Хуки ZCode ──► hooks/rpc-hook.mjs ──► state.json ──► bin/rpc-daemon.mjs ──► Discord IPC
(6 событий)    (пишет файл состояния)                (держит живое соединение)
```

- **Хуки** (`SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUseFailure`, `PermissionRequest`, `Stop`) при каждом событии обновляют маленький файл состояния.
- **Демон** держит постоянное соединение с локальным IPC-сокетом Discord (unix-сокет на Linux/macOS, named pipe на Windows) и применяет обновления статуса. Он сам переподключается при перезапуске Discord, подхватывает изменения конфига на лету, пингует соединение для обнаружения «зомби»-сокетов и гасит статус после `idle_timeout_min` минут без активности.
- Повторяющиеся события дедуплицируются по отпечатку — Discord не спамится.
- Содержимое `tool_input` **никогда** не уходит в Discord (защита секретов). Превью промпта опционально и обрезается.

**Ноль зависимостей** — чистый Node.js (тот же рантайм, на котором работает сам ZCode).

## Требования

- [ZCode](https://z.ai) с поддержкой плагинов
- Node.js (поставляется вместе с ZCode)
- Десктопный Discord (**обычный или Vesktop** — работают оба), запущенный локально

## Установка

### Вариант A — через UI плагинов (рекомендуется)

1. В ZCode открой **Settings → Plugins → «+ New»** (Add marketplace).
2. Вставь этот репозиторий: `z3ntorra/zcode-discord-rpc` (подойдёт любой GitHub `owner/repo`, git-URL или локальный путь).
3. Плагин появится в списке маркетплейса → **Install** → включи.
4. Перезапусти сессию ZCode (или просто переключи), чтобы хуки зарегистрировались.

Если раньше ставил вручную (вариант Б), удали запись `plugins.dirs` из конфига, чтобы копии не дублировались.

### Вариант Б — вручную (удобно для разработки)

Склонируй репозиторий и пропиши папку плагина в конфиге ZCode `~/.zcode/cli/config.json` (на Windows: `%APPDATA%\.zcode\cli\config.json`):

```json
{
  "plugins": {
    "dirs": ["/путь/к/zcode-discord-rpc"]
  }
}
```

Проверка: `zcode plugins list` должен показать `zcode-discord-rpc@inline [enabled]` с `hooks: 6`. Перезапусти сессию (или переключи её), чтобы хуки зарегистрировались.

**Всё** — в плагин вшито общее Discord-приложение, поэтому статус работает сразу: ничего создавать в дев-портале не надо. Запусти сессию и глянь в профиль.

## Опционально: своё приложение (свой брендинг)

Хочешь другое название или свою картинку? Создай приложение в [Discord Developer Portal](https://discord.com/developers/applications) (2 минуты), скопируй **Application ID** и пропиши в конфиге:

```json
{
  "client_id": "твой-application-id",
  "large_image_key": "имя-ассета"
}
```

Демон подхватывает конфиг на лету. Или запусти слэш-команду `/zcode-discord-rpc:setup` — агент проведёт по шагам.

> **Vesktop/Vencord:** встроенный arRPC-мост работает со вшитым ID из коробки, как и официальный клиент. Один нюанс: Discord-клиенты кэшируют список ассетов на сессию — после выхода нового ассета (или загрузки своего) перезапусти Discord один раз, иначе вместо иконки будет «?».

## Конфигурация

Файл: `~/.config/zcode-discord-rpc/config.json` (Linux/macOS) или `%APPDATA%\zcode-discord-rpc\config.json` (Windows). Оба пути переопределяются переменной `ZCODE_DISCORD_RPC_DIR` (тогда конфиг и рантайм-файлы лежат в одной папке).

При первой установке файл создаётся **с комментами**. Полнострочные `//` комменты разрешены в любом месте, всё меняется на лету (пара секунд).

### Шаблоны строк

Обе строки статуса — шаблоны с переменными:

| Переменная | Значение |
|---|---|
| `{project}` | Папка текущего проекта |
| `{prompt}` | Первая строка твоего последнего промпта (пуста при `show_prompt: false`) |
| `{tool}` | Чем занят агент с инструментами сейчас, напр. `Running a shell command` |
| `{auto}` | Вшитый умный статус: промпт → инструмент → простой |

```jsonc
{
    // строка 1 (верхняя)
    "details_template": "Working on {project}",

    // строка 2 (нижняя). "{auto}" = как было.
    // Не хочешь светить промпт? Поставь "{tool}" или любой свой текст:
    "state_template": "{tool}",

    // используется, когда шаблон после подстановки пустой
    "fallback_text": "ZCode"
}
```

### Все поля

| Поле | По умолчанию | Описание |
|---|---|---|
| `client_id` | *(вшитое приложение)* | Discord Application ID. Пусто = общее приложение плагина (zero-setup). Своё — для личного брендинга. Подхватывается на лету. |
| `details_template` | `"Working on {project}"` | Строка 1 (верхняя). |
| `state_template` | `"{auto}"` | Строка 2 (нижняя). |
| `fallback_text` | `"ZCode"` | Используется, когда шаблон после подстановки пустой. |
| `large_image_key` | `"apple-icon"` | **Имя ассета** для большой иконки (`none` — скрыть). |
| `large_image_text` | `"ZCode CLI"` | Подпись большой иконки. |
| `small_image_key` | `""` | Имя ассета малой иконки (пусто — скрыта). |
| `show_prompt` | `true` | Главный выключатель переменной `{prompt}` (прячет её и из state-файлов). |
| `max_prompt_len` | `80` | Лимит длины превью промпта. |
| `idle_timeout_min` | `60` | Минуты без активности до снятия статуса. |

Рантайм-файлы: `~/.cache/zcode-discord-rpc/` (Linux/macOS) или `%LOCALAPPDATA%\zcode-discord-rpc\` (Windows): `state.json`, `daemon.pid`, `daemon.log`, `hook-trace.log`.

## Отладка

- `tail -f ~/.cache/zcode-discord-rpc/daemon.log` (или путь выше для Windows) — ожидаются строки `daemon started` и `connected to Discord`. Ошибки коннекта и RPC пишутся сюда же.
- `hook-trace.log` — каждое срабатывание хука, удобно проверять, что хуки стреляют.
- Статуса нет совсем: загляни в `daemon.log` (там пишутся ошибки коннекта) и проверь, что `zcode plugins list` показывает плагин включённым с `hooks: 6`.
- Вместо иконки «?»: перезапусти Discord после загрузки ассета и проверь, что `large_image_key` — **имя** ассета (не числовой ID).
- Остановить демон: `kill $(cat <runtime>/daemon.pid)` — перезапустится при следующем событии сессии.
- Ручной тест хука:
  ```bash
  printf '%s\n' '{"hook_event_name":"PreToolUse","session_id":"t1","cwd":"/tmp/proj","tool_name":"Bash"}' \
    | node hooks/rpc-hook.mjs
  ```

## Ограничения

- Несколько параллельных сессий ZCode делят один статус («кто последний, тот и прав»).
- Название «игры» в профиле — имя твоего Discord-приложения.
- Хуки регистрируются на старте/resume сессии — если поставил плагин посреди сессии, переключи или перезапусти её.
- `Stop`-хук сессии, начатой до v1.1.0, может ссылаться на старый Python-хук; в комплекте совместимый шим (`hooks/rpc-hook.py`), который безопасно делегирует в Node-версию.
